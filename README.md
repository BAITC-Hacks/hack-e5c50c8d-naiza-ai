# Аким на 5 часов

## Краткое описание

Городскому управленцу или команде на хакатоне нужно за два условных года распределить один и тот же короткий бюджет между транспортом, экологией, соцсферой, безопасностью и сервисами и сразу увидеть, как это меняет город.

«Аким на 5 часов» — веб-симулятор. Все начинают с бюджета **100** и одного синтетического набора: пять районов и десять показателей. Команда выбирает ровно пять мероприятий. Город отвечает баллом **Score**: 70% — средний уровень, 30% — самый слабый район, минус один балл за каждый показатель ниже 40.

Районы условные. Это не официальная статистика, персональных данных в проекте нет.

## Что реализовано

- Каталог из 14 мер. Семь правил набора: бюджет 100, ровно пять мер, без повторов, район обязателен только для районных мер, не больше двух мер одного направления, три запрещённые пары, порядок не важен.
- Недопустимый набор балл не получает: валидатор возвращает причину. Карточка, которая нарушает правило, не добавляется.
- Лаг. За 8 кварталов мера успевает на долю (8 − L) / 8. Три синергии прибавляются целиком и лагом не режутся.
- Живой Score только у допустимой пятёрки. База без действий — 52,56.
- Схема пяти районов и таблица «было / стало».
- Журнал: синергии, критические провалы, напоминание про лаг.
- Доклад: сильные стороны, риски, последствия на 8 кварталов и три реплики вымышленных жителей.
- Совет из четырёх агентов и секретаря, если задан ключ. Секретарь может открыть карточку района. Числа доклада берутся из журнала.
- Запасной доклад из журнала, если ключа нет, ответ не сошёлся со схемой или совет не успел.
- «Тень другого решения»: соседние допустимые наборы с пересчитанной дельтой.
- Полка команд на этой машине и печать доклада на одну страницу.
- Страница «Как считается» с формулой, базой и примером методики.
- Кнопки «Пример методики» и «Дешёвый набор».
- Тесты Vitest и команда `npm run demo`.

## Как работает решение

1. На старте видны бюджет 100, базовый Score 52,56 и пять районов. Два провала ниже 40 — школы и поликлиники Нуры.
2. Команда набирает пять мер. Для районной меры выбирает район на схеме. Городская мера действует на всех.
3. «Запечатать набор» открывает доклад. Движок применяет лаг и синергии, обрезает показатели в 0…100, считает индексы районов и Score.
4. Если ключ задан, совет объясняет уже посчитанный журнал. Иначе остаётся доклад из этого журнала.
5. Можно подставить соседний набор, сохранить прогон и напечатать доклад.

Пример из методики (школа и поликлиника в Нуре, камеры в Нуре, платформа обращений, чистое топливо в Сарыарке) стоит 95 и даёт Score около 56,5. Синергия камер и платформы срабатывает, критический штраф обнуляется.

## Технологии

- TypeScript, React 19, Next.js 15 (App Router), Tailwind CSS 4
- Шрифты Fraunces и Source Sans 3 из пакетов `@fontsource`
- Vitest, tsx
- Zod для проверки ответов совета
- Пакет `openai` как клиент к OpenAI-совместимому API
- Модель совета: `grok-4.7` через `https://api.x.ai/v1`, ключ `XAI_API_KEY`, имя модели можно переопределить переменной `XAI_MODEL`

В репозитории нет вызовов API OpenAI (`api.openai.com`) и API NVIDIA. Ключи этих сервисов проект не читает.

## Архитектура проекта

```
браузер (старт, набор из пяти мер, доклад, формула, полка)
        │
        ▼
validate() / simulate() / recommend()     lib/engine
        │  чистые функции, без сети и без ключа
        ▼
журнал: Score, средний, пол, N_crit, синергии, вклады мер
        │
        ├─ запасной доклад                         lib/ai/fallback.ts
        │
        └─ POST /api/analyze
              четыре агента параллельно, затем секретарь
              инструмент readDistrict читает только срез журнала
              POST /api/runs → data/runs.json на этой машине
```

Данные лежат в `data/city.json`, версия `astana-rules-v2`. Экраны: `/`, `/decide`, `/report`, `/method`, `/compare`.

Веса показателей: T1 0,10, T2 0,10, E1 0,09, E2 0,11, S1 0,11, S2 0,11, B1 0,09, B2 0,09, C1 0,10, C2 0,10. По направлениям это транспорт 0,20, экология 0,20, соцсфера 0,22, безопасность 0,18, сервисы 0,20.

## Установка и запуск

Нужен Node.js LTS. Из папки проекта в PowerShell:

```powershell
npm install
copy .env.example .env
npm test
npm run demo
npm run dev
```

Открыть http://localhost:3000

На Windows после установки Node.js LTS можно просто открыть файл `start-local.cmd` двойным кликом. Он проверит зависимости, создаст локальный `.env` из `.env.example`, запустит `npm run dev` в отдельном окне и откроет приложение в браузере. Если порт 3000 уже занят работающим приложением, новый сервер не запускается — открывается существующий адрес.

Файл `.env` в git не попадает. Ключ можно оставить пустым. Для живого совета туда записывают ключ xAI и не публикуют его в GitHub:

```
XAI_API_KEY=
XAI_MODEL=grok-4.7
```

После `npm run build` сервер запускается командой `npm start`.

## Как проверить решение

Без браузера:

```powershell
npm test
npm run demo
```

`npm run demo` печатает базу, пример методики и дешёвый набор. Тесты фиксируют базу 52,56, два провала S1 и S2 в Нуре, пример стоимостью 95 со Score между 56,4 и 56,6 и синергией M10+M12, дешёвый набор за 61, отказ набора дороже 100, запрет повторов, третьей меры одного направления и трёх конфликтов.

В браузере:

1. Открыть старт. Score 52,56, пол — Нура, провалов 2.
2. «Открыть набор», затем «Пример методики». Score около 56,54, остаток 5, провалов 0.
3. Снять одну меру и попробовать вторую линию ЛРТ вместе с выделенными полосами. Набор такую пару не примет.
4. «Запечатать набор». В докладе есть сильные стороны, риски и реплика. Без ключа видна пометка, что совет работает по журналу.
5. Открыть «Тень другого решения». Соседний набор можно подставить, Score пересчитает движок.
6. «Оставить прогон на полке» и открыть сравнение.

Повторный разбор недопустимого набора через `POST /api/analyze` возвращает статус 400 и не вызывает модель.

## Данные и интеграции

- `data/city.json`: пять районов (Есиль, Алматы, Сарыарка, Байконур, Нура), доли населения, десять показателей 0–100, 14 мер с ценой, лагом и эффектами, три синергии, три несовместимости, пять вымышленных жителей.
- Шкала показателей направлена одинаково: 100 — нет проблемы. Пробки и смог уже перевёрнуты.
- Внешний сервис один: xAI, `https://api.x.ai/v1`, модель `grok-4.7`. Вызов идёт только с сервера и только после успешного `simulate()`.
- Прогоны команд пишутся в `data/runs.json` на машине, где запущен сервер. Файл в `.gitignore`.
- Развёрнутого адреса нет. Карты, платёжные сервисы, OpenAI API и NVIDIA API не подключены.

## Ограничения

- Нет общей полки между компьютерами и нет учётных записей.
- Без `XAI_API_KEY` и сети живой совет не работает. Score, журнал, тень, полка и доклад по журналу при этом остаются.
- Интерфейс на русском.
- Цифры синтетические и не являются официальной статистикой.
- Печать — одна страница браузера. Отдельный файл презентации проект не собирает.
- Неизрасходованный остаток Score не повышает. Отдельного события вроде ледяного дождя в этой версии нет: горизонт задан лагом мер.
- Публичной deployed-версии нет.
